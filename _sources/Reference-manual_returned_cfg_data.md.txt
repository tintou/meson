# Configuration data object (`cfg_data`)

This object encapsulates
configuration values to be used for generating configuration files. A
more in-depth description can be found in the [the configuration wiki
page](Configuration.md).


## Returned by

Configuration data object objects are returned by the following functions and methods:
- [[configuration_data]]




## Configuration data object methods

<p style="padding: 7.5px; margin: 0px;"></p>

Returns the value of `varname`, if the
value has not been set returns `default_value` if it is defined
*(since 0.38.0)* and errors out if not

### cfg_data.set10()

Is the same as [[cfg_data.set]] but the value
is either `true` or `false` and will be written as 1 or 0,
respectively

<p style="padding: 5px; margin: 0px;"></p> <!-- A bit of space because we remove the top margin below -->
<div style="display: flex;">
  <h4 style="margin-top: 0px;">Signature</h4>
  <div style="flex-grow: 1;"></div>
  <div class="d-flex flex-column align-items-center gap-1">

</div>
</div>

<pre><code class="language-meson"># Is the same as [[cfg_data.set]] but the value
[[#@void]] set10(
  [[#@str]]                                                                          <a href="#set10_varname"><b>varname</b></a>,     # The name of the variable to set
  [[#@bool]] | [[#@int]]                                                                   <a href="#set10_value"><b>value</b></a>,       # The value to set as either `1` or `0`

  # Keyword arguments:
  <a href="#set10_description"><b>description</b></a> : [[#@str]]                                   # Message / Comment that will be written in the
)</code></pre>



```{warning}
numeric values < 0 have the surprising behavior of being converted to `true`, values > 1 have the more expected but unintentional behavior of being interpreted as `true`.
```
